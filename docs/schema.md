# Ops Memory schema

Ops Memory is a directory of markdown files, git-tracked, that is the single source of truth about VMs and deployments. Claude Code and Mochi both edit it. Code: `src/lib/opsMemory/`. Templates: `templates/`.

## Layout

```
ops-memory/
├── INDEX.md            # generated by Mochi (generateIndex); do not edit by hand
├── vms/<name>.md       # one file per VM
├── projects/<name>.md  # one file per project
├── changelog/YYYY-MM.md  # one file per month, newest entry first
├── inbox.md            # quick notes / review stubs, triaged later
└── .mochi/
    ├── config.json     # non-secret settings only
    └── schema-version
```

## Frontmatter

### VM (`type: vm`)

| Field | Required | Notes |
|---|---|---|
| `type` | yes | `vm` |
| `name` | yes | Letters, digits, `.` `_` `-`; must match the file name |
| `provider` | no | e.g. DigitalOcean, AWS, on-prem |
| `host` | no | Hostname or IP. **Never credentials** |
| `os` | no | |
| `last_updated` | no* | `YYYY-MM-DD` (*Mochi and Claude always set it) |
| `updated_by` | no | `claude-code`, `mochi`, `manual` |

### Project (`type: project`)

| Field | Required | Notes |
|---|---|---|
| `type` | yes | `project` |
| `name` | yes | Same rule as VMs |
| `repo` | no | URL or path |
| `deployed_on` | no | List of VM `name`s |
| `last_updated` | no* | `YYYY-MM-DD` |

Unknown fields are allowed and are preserved exactly on every edit.

## Body sections

VM: Purpose · Deployed (table) · Config Notes · Recent Changes · Open Issues / TODO.
Project: Summary · Stack · Deploy Procedure · Recent Changes · Known Issues.

## Changelog entries

`changelog/YYYY-MM.md` starts with `# Changelog YYYY-MM`, then one bullet per change, newest first:

```
- 2026-10-07 — Upgraded nginx to 1.27 (vm: prod-api-01, project: nexus-ai, tag: upgrade, by: claude-code)
```

Tags: `deploy`, `config`, `incident`, `upgrade`.

## Hard rule: no secrets

Files store **names and locations only** (e.g. "`DATABASE_URL` is set in `/etc/app/.env`"), never values. Mochi's secret scanner (Stage 2) blocks saves that contain secrets.

## Library behaviour

- `parseMarkdown` / `serializeMarkdown`: lossless split into `open | frontmatter | close | body`. An unmodified document serializes byte-identically (CRLF, BOM, comments, unknown keys, trailing whitespace preserved).
- `setField` / `removeField`: line-based edits of top-level keys; every other byte stays untouched. Trailing comments on simple values are kept.
- `readFrontmatter`: YAML 1.2 core parse; dates stay strings.
- `validateFrontmatter` / `parseEntry`: schema checks (type, name, date, `deployed_on`).
- `generateIndex(entries, generatedOn)`: deterministic INDEX.md (sorted, LF, pipes escaped, VM ↔ project cross-references).
